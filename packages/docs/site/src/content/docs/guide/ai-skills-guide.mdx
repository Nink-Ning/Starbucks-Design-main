当前可以支持以下任务：

- 根据产品需求生成后台产品 Demo；
- 根据 Figma 设计生成 React 或 Vue 页面；
- 生成无需安装依赖的单文件 HTML Preview；
- 复用已有基础组件和业务组件；
- 判断 Modal、Drawer、侧栏或新页面等容器形式；
- 设计筛选、表格、批量操作、表单和详情页结构；
- 优化已有组件与 Figma 的视觉一致性；
- 检查 React / Vue 公共 API 和行为是否一致；
- 生成 Docs Demo、测试计划和实施文件清单；
- 审查 AI 生成代码是否符合设计系统规则。

AI Skill 会优先复用已有资产，避免重复创建相似组件。

## 4. 开始使用

### 第一步：打开项目

在 VS Code 或 Codex 中打开项目根目录：

```text
starbucks-design-main
```

建议每个新任务创建一个独立对话，避免旧任务上下文影响当前生成结果。

### 第二步：明确调用总控 Skill

在任务开头加入：

```text
请使用 skills/starbucks-design/SKILL.md 完成下面的任务。
```

也可以使用更自然的表达：

```text
请基于 Starbucks Design Skill 生成产品 Demo。
```

AI 会根据任务自动选择：

- `starbucks-design-react`
- `starbucks-design-vue`
- `starbucks-design-react-preview`
- `starbucks-design-vue-preview`
- 对应设计决策和专项开发规范

使用者不需要手动指定每个 reference 文件。

### 第三步：提供业务信息

建议至少提供：

```text
页面名称：
使用角色：
核心任务：
页面类型：
需要展示的数据：
主要筛选条件：
主要操作：
是否有批量操作：
是否需要新增或编辑：
参考页面或 Figma：
希望的交付形式：
```

不确定的内容可以留空，让 AI 先给出设计建议。

## 5. 推荐的两阶段工作方式

不要在需求尚未确认时直接要求 AI 完成全部代码。

请使用 skills/starbucks-design/SKILL.md 帮我生成一个产品 Demo。

使用角色：运营人员
核心任务：创建标签、给门店添加标签、查看标签下的门店
页面类型：后台管理列表页

页面需要包括：
1. 左侧标签分组；
2. 右侧门店筛选；
3. 门店表格；
4. 新建标签；
5. 编辑和删除标签；
6. 批量给门店添加标签；
7. 分页；
8. Loading、Empty 和 Error 状态。

请先进行设计决策，说明：
- 为什么使用左右结构；

```text
请使用 Starbucks Design Skill，根据我提供的 Figma 节点完成页面方案分析。

请输出：
1. 页面类型；
2. 布局与容器决策；
3. Figma 元素与现有组件映射；
4. Figma Variables 与 Design Token 映射；
5. 可复用的基础组件和业务组件；
6. 不应该重复创建的组件；
7. React / Vue / Preview 交付方式建议；
8. 预计修改文件；
9. 当前无法确认的视觉信息。

本轮只分析，不修改文件。等待我确认后再生成 Demo。
```

提供 Figma 时，建议同时附上：

- 文件或页面链接；
- 具体 Frame / Node；
- Variables 或 Token 信息；
- 桌面端和窄屏设计；
- 弹层和交互状态；
- 需要重点验收的视觉差异。

## 8. 生成正式 React / Vue Docs Demo

```text
请使用 skills/starbucks-design/SKILL.md 创建“标签管理”页面 Demo。

要求：
1. 优先复用现有 FilterBar、Table、Pagination、Button、Drawer 等能力；
2. 不创建通用 TagManagement 万能组件；
3. React 和 Vue 可见行为保持一致；
4. 使用确定性的本地 Mock 数据；
5. 支持查询、重置、分页、选择和批量操作；
6. 支持 Loading、Empty 和 Error；
7. 支持窄屏；
8. 接入 Docs Preview；
9. 提供源码查看或复制能力。

请先进行只读分析并输出实施计划，不要直接修改文件。
```

## 9. 优化现有页面或组件

```text
请使用 Starbucks Design Skill 对当前页面进行只读审查。

目标：检查页面与 Figma 和设计系统的一致性。

请输出：
1. 当前页面使用的组件；
2. 可以复用但尚未复用的组件；
3. 布局、间距、层级和操作位置问题；

6. Popup / Portal / 样式权重风险；

8. 按影响范围制定的验证计划。

本轮只分析，不修改文件。
```

## 10. AI 会如何选择组件和页面结构

AI 会依次判断：

```text
这是什么任务
→ 属于基础组件、业务组件、页面模板还是业务模块
→ 使用 React、Vue 还是 Preview
→ 是否已有可复用组件
→ 需要哪些设计决策
→ 允许修改哪些文件
→ 需要执行哪些验证
```

常见判断示例：

| 需求 | 通常选择 |
| --- | --- |
| 简单字段填写 | 基础表单页 |
| 字段较多且有明确分组 | 分组表单页 |
| 存在连续步骤和前后依赖 | 分步表单页 |
| 只修改少量字段 | 优先使用弹窗或抽屉 |
| 展示为主、编辑为辅 | 优先使用详情页编辑模式 |
| 搜索、筛选和表格查询 | FilterBar + Table |
| 轻量确认或少量输入 | Modal |
| 与当前页面强关联的复杂编辑 | Drawer |
| 独立复杂流程 | 新页面 |
| 批量操作 | 表格左上方或选择后工具栏 |
| 详情信息较多 | 分区详情页或 Tabs |
| 指标和趋势分析 | Dashboard |

设计决策最终仍需结合实际业务目标，而不是只根据字段数量机械判断。

## 14. 当前限制

### 黄金模板尚未全面开放

`skills/starbucks-design/scripts/` 目前还没有完成验证的页面黄金模板。

因此现阶段 AI 主要基于：

- 总控规则；
- 设计决策；
- 现有组件；
- 已有 Docs Demo；
- 相似页面结构

进行生成，而不是直接套用固定模板。

### Figma 视觉还原需要设计证据

没有 Figma Node、Variables、截图或视觉验收信息时，AI 可以生成符合设计系统的页面，但不能承诺与目标设计稿完全一致。

### 未运行的验证不会自动视为通过

HTML Preview 可用于方案评审，但不等同于正式 React/Vue 工程已经完成测试和构建。

### 部分能力可能存在版本范围

例如某些组件可能已经有逻辑实现，但尚未纳入当前视觉完成范围。使用前应以组件 Docs 和任务分析结果为准。

## 16. 推荐团队流程

```text
产品提供业务目标
→ AI 生成页面方案
→ 设计确认布局和组件
→ AI 生成 Preview
→ 产品与业务评审
→ AI 生成 React / Vue 实现
→ 研发检查和补充测试
→ 设计进行视觉验收
→ 人工授权提交和发布
```

| 角色 | 主要职责 |
| --- | --- |
| 产品经理 | 业务目标、字段、流程、验收标准 |
| 体验设计师 | 页面结构、设计决策、Figma、视觉验收 |
| 前端研发 | 工程实现、API、测试、构建和兼容性 |
| AI Skill | 规则路由、组件选择、代码生成、检查和报告 |

## 17. 最佳实践

1. 一个对话尽量只处理一个明确任务；
2. 先分析、后修改；
3. 先确认页面结构，再生成完整代码；
4. 明确 React、Vue 或 Preview 交付形式；
5. 提供真实字段、数据和操作；
6. 提供 Figma 节点而不是只提供文件首页；
7. 明确允许修改的文件范围；
8. 不让 AI 自动提交或发布；
9. 不把未运行的测试描述为通过；
10. 生成结果必须经过产品、设计和研发共同验收。
