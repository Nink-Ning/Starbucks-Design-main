DesignKit Starter 的目标不是让 AI 从模糊的“DesignKit 风格”重新设计页面，而是先完成范围判断、能力确认、模板与 Shell 决策，再从批准参考进入实现与验证。

<div class="sb-ai-skill-page-marker" aria-hidden="true"></div>

## 使用前准备

1. 从[产品经理启动包](../ai-skills-releases/)确认版本状态。V1-r3 已完成生产发布；下载入口提供 `designkit-starter-v1-r3.zip`。
2. 解压后将完整目录交给 AI Agent，不要只复制某一个 Skill 或示例文件。
3. 用自然语言说明页面目标、使用角色、要展示的数据和主要操作。

如果你还不确定应该使用哪个启动包，请先阅读[如何选择启动包](../ai-skills-selection/)。

AI 只能实现 Capability Registry 中存在、且当前 Template 允许的能力。批准参考是标准实现起点；业务数据可以替换，但不能据此推断某项新能力已经发布。

## 默认生成方式

例如提出：

> 帮我做一个商品管理列表页。

在没有额外导航要求时，Starter 默认使用：

```text
Default Application Shell
+
approved Basic List
```

用户不需要重复指定 Top Navigation、Side Navigation、标准 Table reference 或默认页面间距。AI 应直接复用批准的 Shell 与模板，只替换商品字段、数据、状态和适用操作。

## Shell 模式

| 模式 | 何时使用 | 生成结果 |
| --- | --- | --- |
| `default` | 常规企业应用页面，也是默认值 | 公司标准 Application Shell + 已批准页面模板 |
| `content-only` | 你的应用已经拥有 Top / Side navigation | 只移除 Application Shell，保留完整页面内容与层级 |
| `none` | 明确需要 standalone / 独立 Demo | 不生成 Application Shell |

只有这三种模式。`content-only` 不等于删除页面层级：一个 Level 2 Form 仍会保留返回、页面标题和表单，只是不再包含 Top 与 Side。

## 页面层级

| 信息架构深度 | 默认页面上下文 |
| --- | --- |
| Level 1 | 页面标题 + 可选的上下文帮助；无返回、无面包屑 |
| Level 2 | icon-only 返回 + 页面标题 + 可选的上下文帮助；无面包屑 |
| Depth ≥ 3 | 只使用面包屑；无独立页面标题、无返回 |

页面层级由业务信息架构决定，而不是由模板名称决定。例如“门店列表 → 门店详情”中的详情是 Level 2；“活动管理 → 活动详情 → 参与门店详情”中的参与门店详情是 Depth 3。Detail 并不总是 Level 2。

## 明确覆盖与默认能力

如果你提出“商品图片改成方形，其余保持默认”，AI 只应改变媒体形状，并继续保留批准的 Shell、Header、Toolbar、Card anatomy、Selection 和 Footer。未明确要求的标准结构不应一起被重新设计。

同时，Starter 支持某项能力不代表每个页面都要默认启用它。例如存在选择与批量操作能力，不代表每个 Card List 都应该自动增加批量动作；是否启用仍取决于业务场景和模板默认值。

## 如何描述需求

尽量同时告诉 AI 以下信息：

- 目标：这次需要评审或验证什么；
- 使用者：谁会使用这个页面；
- 数据：页面中需要展示哪些关键字段；
- 操作：用户需要搜索、选择、编辑或执行哪些动作；
- 边界：是否只需要 HTML Demo，是否明确不需要真实接口。

例如：

> 帮我设计一个商品管理页面，用于产品评审。需要展示商品图片、名称和状态，并验证当前列表内的多选与批量操作。使用公司默认应用框架，只需要本地 HTML Demo，不接真实接口。

## 推荐场景

### 产品评审

> 帮我设计一个商品管理页面。

适合快速形成可讨论的页面方案，并通过 HTML Demo 对齐信息结构和主要操作。

### 页面探索

> 我要一个运营后台列表方案。

适合让 AI 先判断任务范围和页面模板，再给出符合 Starter 边界的方案。

### 交互验证

> 商品需要图片展示和批量操作。

适合让 AI 判断视觉浏览、当前结果选择和本地批量操作应采用哪种已支持的模式，并在生成后执行 Validation 检查。

## 结果检查

生成完成后，至少确认：

- 页面是否复用了批准的 Shell 与已登记模板；
- 操作是否落在该模板允许的范围内；
- HTML Demo 是否可以在浏览器中打开；
- 明暗主题和不同宽度下是否仍然可用；
- 未实际检查的项目是否明确标记为未验证。

:::caution[Starter 边界]
Starter 不提供自定义应用 Shell 架构、Navigation API、真实 Router、权限路由、后端动态菜单或系统切换集成，也不提供 React/Vue 工程开发、组件 API 集成、真实导出、真实后端/API 或生产部署。前端开发启动包仍为 Coming Soon。超出范围时，AI 应说明边界并停止假设。
:::
