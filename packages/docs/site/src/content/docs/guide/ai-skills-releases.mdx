## 默认生成与批准参考

常规企业应用页面默认使用标准 Application Shell 和与任务匹配的批准模板。用户只需描述业务目标、关键数据和操作，不需要重新指定 Top、Side、标准间距或组件组合。

批准模板是标准答案：业务字段、数据、状态和文案可以变化，页面 anatomy、交互归属与响应式关系默认保持一致。明确提出的覆盖只影响被请求的属性。例如“商品图片改成方形，其余保持默认”只改变媒体形状，不应同时重做 Shell、Header、Toolbar、Card、Selection 或 Footer。

能力存在也不等于默认启用。选择、批量操作或其他可选能力只在场景需要、且模板允许时出现。

## 页面模板说明

| 模板 | 适用场景 | 默认组合重点 |
| --- | --- | --- |
| Basic List | 管理列表、搜索/筛选、表格操作与分页 | Toolbar → Table → Pagination 位于同一批准内容区域；可导航名称使用 Link，关键标识与操作列在横向滚动时保持可用。 |
| Card List | 需要图片或卡片浏览、选择与管理的集合 | 响应式卡片排列、批准的卡片 anatomy、默认媒体处理、选择与批量操作。 |
| Basic Detail | 聚焦查看单一对象 | 稳定的多列信息布局与统一字段标签/内容对齐。 |
| Basic Form | 标准创建与编辑 | 同一表单家族内保持一致的字段、内容区域与操作关系。 |
| Grouped Form | 分区较多的复杂编辑 | 在标准表单外层规则内组织分组内容。 |
| Step Form | 多步骤创建或配置 | Steps、当前步骤内容与底部操作区域保持批准关系。 |
| Drawer Form | 轻量上下文编辑 | Drawer 拥有最终操作区域，内部 Form 不生成重复 Footer。 |

Table List 的全选来自 Table header；Card List 没有 Table header，因此选择控制属于 Card Toolbar，页面只保留一个可见选择汇总。Card Toolbar 批量操作使用次要/描边层级，优先级由直接显示或进入 More 表达，而不是提升为页面主按钮。

## 主题、响应式与多页面演示

Light / Dark 使用同一份批准结构和既有 DesignKit 主题机制，不是两套页面设计，也不需要用户单独请求“深色版”。标准 Shell 和模板包含已验证的响应式关系，但不承诺 Drawer hamburger、底部导航或新的移动 Navigation API。

Starter 包自身携带 AI 所需的规则与参考，不要求访问完整 DesignKit 仓库。V1-r3 已通过“活动管理”等综合业务场景验证，可以帮助 AI 生成结构连贯的静态多页面演示；该场景是验证证据，不是新增官方模板，也不代表真实 Router 或完整 SPA 工程。

## 当前暂不支持

以下项目明确不属于当前产品经理 Starter：

- 自定义 Application Shell 架构或完整 Navigation API；
- 真实客户端 Router、权限路由、后端动态菜单或后端系统切换集成；
- Dashboard 与 Result Page；
- React/Vue 工程、组件 API 集成和 Developer Starter；
- 真实 Export、真实后端/API、上传和生产部署；
- 复杂生产应用状态管理；
- Capability Registry 中标记为 `OUT` 或未登记的能力。

前端开发启动包仍为 Coming Soon，V1-r3 不提供或暗示上述工程能力。
