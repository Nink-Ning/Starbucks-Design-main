AI Skill 使用指南

Starbucks Design AI Skill

把产品需求、Figma 设计和业务场景转换为可验证的设计系统产物

面向产品、设计和研发的 AI 设计生产规则。它会根据任务自动选择总控 Skill、框架 Skill、 Preview Skill、设计决策规则和组件 API，帮助团队更快生成 Demo、Docs 示例和正式工程实现。

分析生成检查报告

边界说明

AI Skill 不是自动发布工具。它负责分析、生成、检查和报告，不会在未经授权的情况下自动提交 Git、创建 PR、升级版本或发布组件包。

1. AI Skill 能做什么

01

生成产品 Demo

根据产品需求生成后台产品 Demo，包含页面结构、核心交互、本地 Mock 数据和主要状态。

02

还原设计实现

根据 Figma 设计生成 React 或 Vue 页面，并完成组件映射、Token 对齐和视觉差异说明。

03

沉淀 Docs 示例

生成真实 React / Vue Docs Demo、测试计划、源码查看入口和实施文件清单。

04

审查设计系统规则

检查 React / Vue 公共 API、行为一致性、样式覆盖、Popup/Portal 风险和验收状态。

当前可以支持以下任务：

  • 根据产品需求生成后台产品 Demo；
  • 根据 Figma 设计生成 React 或 Vue 页面；
  • 生成无需安装依赖的单文件 HTML Preview；
  • 复用已有基础组件和业务组件；
  • 判断 Modal、Drawer、侧栏或新页面等容器形式；
  • 设计筛选、表格、批量操作、表单和详情页结构；
  • 优化已有组件与 Figma 的视觉一致性；
  • 检查 React / Vue 公共 API 和行为是否一致；
  • 生成 Docs Demo、测试计划和实施文件清单；
  • 审查 AI 生成代码是否符合设计系统规则。

AI Skill 会优先复用已有资产，避免重复创建相似组件。

2. 谁可以使用

产品经理和业务人员

适合快速验证需求、页面结构和业务流程。不要求具备编程能力，也不要求安装 Node.js。

  • 单文件 HTML Preview
  • 页面方案分析
  • 交互流程 Demo
  • 需求评审 Demo

体验设计师

适合完成设计决策、组件映射、Figma 还原和设计验收。

  • 页面结构分析
  • 设计决策审查
  • Figma 到组件映射
  • 视觉一致性检查

前端研发

适合完成正式工程实现、测试和构建。

  • React 或 Vue 工程代码
  • 公共 API 对齐
  • 组件测试
  • Docs 接入和构建检查

3. 三种使用模式

模式一

快速 Preview

适用于产品经理、业务人员和早期方案评审。最终产物通常为一个可直接打开的单文件 HTML。

  • 不需要安装 Node.js；
  • 不修改正式组件库源码；
  • 适合快速确认页面结构和交互；
  • 可以使用本地 Mock 数据；
  • 不代表已经完成正式工程验收。
模式二

Docs Demo

适用于设计系统站点展示和跨角色评审。

  • 使用真实 React / Vue 组件；
  • 可以切换框架查看效果；
  • 适合沉淀业务组件和页面模板；
  • 需要项目开发环境。
模式三

工程实现

适用于正式研发交付。

  • 使用正式组件 API；
  • 按任务影响范围补充测试；
  • 需要明确修改文件白名单；
  • 版本、提交和发布必须单独授权。

5. 推荐的两阶段工作方式

不要在需求尚未确认时直接要求 AI 完成全部代码。

阶段一

方案分析

产品、设计和研发先确认页面类型、页面结构、布局方式、容器选择、组件清单、核心操作、状态设计、响应式策略、预计修改文件和当前缺失信息。

阶段二

生成 Demo 或代码

确认后再要求 AI 按方案生成 Demo 或进入实施，并约束只修改已批准的文件白名单。

两阶段方式可以减少错误组件、错误容器、无效代码和超范围修改。

11. 如何验收 AI 生成结果

产品验收

  • 是否解决核心业务任务；
  • 字段和流程是否完整；
  • 主操作是否清晰；
  • 是否存在多余步骤；
  • 数据和文案是否符合业务定义。

设计验收

  • 页面结构和信息层级；
  • Modal、Drawer、Tabs 等容器是否合理；
  • 筛选、表格和批量操作位置；
  • 组件是否来自设计系统；
  • Figma Variables 和 Token 是否正确；
  • 桌面端和窄屏是否可用；
  • Loading、Empty、Error、Disabled 等状态是否完整。

研发验收

  • 是否使用真实组件 API；
  • React / Vue 行为是否一致；
  • 是否修改了公共 API；
  • 是否存在私有 .arco-* 覆盖；
  • 是否存在不必要的 !important；
  • Popup / Portal 是否正确；
  • 未运行的验证是否被明确标记。

12. 结果状态说明

COMPLETE

任务已完成，要求的实现和适用验证均已完成。

CONDITIONAL

主体内容已完成，但仍依赖 Figma、浏览器验证、环境或业务确认。

BLOCKED

缺少关键输入或环境，继续执行可能产生错误结果。

UNVERIFIED

代码或方案已经生成，但测试、构建或浏览器检查尚未执行。不要把它理解为“已经验收通过”。

14. 当前限制

黄金模板尚未全面开放

skills/starbucks-design/scripts/ 目前还没有完成验证的页面黄金模板。

因此现阶段 AI 主要基于：

  • 总控规则；
  • 设计决策；
  • 现有组件；
  • 已有 Docs Demo；
  • 相似页面结构

进行生成，而不是直接套用固定模板。

Figma 视觉还原需要设计证据

没有 Figma Node、Variables、截图或视觉验收信息时，AI 可以生成符合设计系统的页面，但不能承诺与目标设计稿完全一致。

未运行的验证不会自动视为通过

HTML Preview 可用于方案评审，但不等同于正式 React/Vue 工程已经完成测试和构建。

部分能力可能存在版本范围

例如某些组件可能已经有逻辑实现，但尚未纳入当前视觉完成范围。使用前应以组件 Docs 和任务分析结果为准。

15. 常见问题

使用 AI Skill 需要懂代码吗？

生成单文件 HTML Preview 不需要。正式修改 React/Vue 工程时，建议由研发参与最终验收。

必须安装 Node.js 吗？

生成 Preview 通常不需要。运行 Docs、测试和正式构建需要项目规定的开发环境。

必须把代码推送到 GitHub 才能使用吗？

不需要。Codex 可以直接在本地项目中读取和使用 Skill。

AI 会自动提交代码吗？

不会。除非使用者明确授权，否则不应执行 git add、commit、push、创建 PR、版本升级或发布。

产品经理只提供一句话需求可以吗？

可以开始，但生成质量会受到限制。建议至少补充用户角色、核心任务、数据、操作和交付形式。

应该选择 React 还是 Vue？

已有项目使用哪个框架，就优先选择对应 Skill。只做快速评审时，可以选择 Preview。

可以同时生成 React 和 Vue 吗？

可以。需要明确要求双端可见行为一致，并分别检查 Props、Events、Slots、DOM 和 Popup 行为。

AI 生成的 Demo 可以直接上线吗？

不能直接等同于上线版本。正式上线前仍需完成业务、设计、研发、测试和发布流程。

16. 推荐团队流程

角色主要职责
产品经理业务目标、字段、流程、验收标准
体验设计师页面结构、设计决策、Figma、视觉验收
前端研发工程实现、API、测试、构建和兼容性
AI Skill规则路由、组件选择、代码生成、检查和报告

17. 最佳实践

  1. 一个对话尽量只处理一个明确任务；
  2. 先分析、后修改；
  3. 先确认页面结构，再生成完整代码；
  4. 明确 React、Vue 或 Preview 交付形式；
  5. 提供真实字段、数据和操作；
  6. 提供 Figma 节点而不是只提供文件首页；
  7. 明确允许修改的文件范围；
  8. 不让 AI 自动提交或发布；
  9. 不把未运行的测试描述为通过；
  10. 生成结果必须经过产品、设计和研发共同验收。
