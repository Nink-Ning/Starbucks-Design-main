筛选栏 FilterBar

筛选栏用于列表、表格或数据内容区域上方的高频条件筛选。

基本用法

基本用法只展示 FilterBar 的核心行为：manual 模式、Draft / Active 区分、查询、重置、展开与收起。

Show code
代码示例 
import { useMemo, useState } from 'react';
import { FilterBar, Table } from '@sbux/starbucks-design-react';
import type { FilterFieldSchema, FilterValue } from '@sbux/starbucks-design-react';

const fields: FilterFieldSchema[] = [
  { type: 'input', name: 'keyword', label: '关键词', placeholder: '门店 / 编号', priority: 1 },
  {
    type: 'select',
    name: 'status',
    label: '状态',
    priority: 0,
    options: [
      { label: '营业中', value: 'open' },
      { label: '筹备中', value: 'pending' },
      { label: '已停用', value: 'closed' },
    ],
  },
  {
    type: 'multiSelect',
    name: 'channel',
    label: '渠道',
    priority: 2,
    maxTagCount: 1,
    options: [
      { label: '堂食', value: 'dine-in' },
      { label: '外送', value: 'delivery' },
      { label: '自提', value: 'pickup' },
    ],
  },
  { type: 'date', name: 'createdAt', label: '创建日期', priority: 3 },
  { type: 'dateRange', name: 'period', label: '营业周期', span: 2 },
];

const initialValues: FilterValue = {
  status: 'open',
  channel: ['dine-in'],
  period: ['2026-07-01', '2026-07-29'],
};

const basicColumns = { xs: 1, sm: 3, md: 3, lg: 3, xl: 3, xxl: 3 };

const rows = [
  { id: 'SH-001', name: '上海静安门店', status: 'open', channel: '堂食 / 外送' },
  { id: 'SH-018', name: '上海虹桥门店', status: 'pending', channel: '自提' },
  { id: 'HZ-011', name: '杭州西湖门店', status: 'open', channel: '堂食 / 自提' },
];
const tableColumns = [
  { title: '门店名称', dataIndex: 'name' },
  { title: '门店编号', dataIndex: 'id', width: 120 },
  { title: '渠道', dataIndex: 'channel', width: 160 },
];

export default function Demo() {
  const [draftValues, setDraftValues] = useState<FilterValue>(initialValues);
  const [activeValues, setActiveValues] = useState<FilterValue>(initialValues);
  const visibleRows = useMemo(() => {
    const keyword = String(activeValues.keyword ?? '').trim();
    const status = activeValues.status;
    return rows.filter((row) => {
      const keywordMatched = !keyword || row.name.includes(keyword) || row.id.includes(keyword);
      const statusMatched = !status || row.status === status;
      return keywordMatched && statusMatched;
    });
  }, [activeValues]);

  return (
    <div className="sb-filter-bar-demo sb-filter-bar-demo--basic">
      <FilterBar
        fields={fields}
        value={draftValues}
        activeValues={activeValues}
        defaultValue={initialValues}
        defaultVisibleCount={3}
        columns={basicColumns}
        onValuesChange={setDraftValues}
        onActiveValuesChange={setActiveValues}
      />
      <Table columns={tableColumns} data={visibleRows} pagination={false} rowKey="id" />
    </div>
  );
}
<template>
  <div class="sb-filter-bar-demo sb-filter-bar-demo--basic">
    <FilterBar
      :fields="fields"
      :model-value="draftValues"
      :active-values="activeValues"
      :default-value="initialValues"
      :default-visible-count="3"
      :columns="basicColumns"
      @values-change="handleValuesChange"
      @update:active-values="handleActiveValuesChange"
    />
    <Table :columns="tableColumns" :data="visibleRows" :pagination="false" row-key="id" />
  </div>
</template>

Manual / Change 模式

manual 模式下，字段变化只更新 Draft，点击查询后才更新 Active。基本用法 Demo 已覆盖该模式。

change 模式下，字段变化立即更新 Draft，随后经过 debounce 更新 Active 并提交；默认不展示查询按钮。

Show code
代码示例 
import { useState } from 'react';
import { FilterBar } from '@sbux/starbucks-design-react';
import type { FilterEventMeta, FilterFieldSchema, FilterValue } from '@sbux/starbucks-design-react';

const fields: FilterFieldSchema[] = [
  { type: 'input', name: 'keyword', label: '关键词', placeholder: '输入后自动查询' },
  {
    type: 'select',
    name: 'status',
    label: '状态',
    options: [
      { label: '营业中', value: 'open' },
      { label: '筹备中', value: 'pending' },
    ],
  },
  { type: 'dateRange', name: 'period', label: '统计周期', valueFormat: 'YYYY-MM-DD', span: 2 },
];

const initialValues: FilterValue = { status: 'open', period: ['2026-07-01', '2026-07-29'] };

export default function Demo() {
  const [draftValues, setDraftValues] = useState<FilterValue>(initialValues);
  const [activeValues, setActiveValues] = useState<FilterValue>(initialValues);
  const [events, setEvents] = useState<string[]>(['初始化 active snapshot']);
  const pushEvent = (label: string, values: FilterValue, meta: FilterEventMeta) => {
    setEvents((previous) => [`${label}: ${meta.source} ${JSON.stringify(values)}`, ...previous].slice(0, 5));
  };

  return (
    <div className="sb-filter-bar-demo sb-filter-bar-demo--basic">
      <FilterBar
        fields={fields}
        value={draftValues}
        activeValues={activeValues}
        defaultValue={initialValues}
        submitMode="change"
        debounceMs={300}
        onValuesChange={(values, meta) => {
          setDraftValues(values);
          pushEvent('draft', values, meta);
        }}
        onActiveValuesChange={setActiveValues}
        onSubmit={(snapshot, meta) => pushEvent('submit', snapshot, meta)}
      />
      <div className="sb-filter-bar-demo__evidence-grid" aria-live="polite">
        <div className="sb-filter-bar-demo__evidence">
          <span className="sb-filter-bar-demo__eyebrow">Active</span>
          <code>{JSON.stringify(activeValues)}</code>
        </div>
        <div className="sb-filter-bar-demo__evidence">
          <span className="sb-filter-bar-demo__eyebrow">Event Order</span>
          <ol>
            {events.map((event, index) => <li key={`${event}-${index}`}>{event}</li>)}
          </ol>
        </div>
      </div>
    </div>
  );
}

适用场景

  • 页面主体是列表、表格或数据内容区域。
  • 常用筛选条件通常为 2 到 6 个。
  • 完整条件通常不超过 12 个。
  • 条件字段稳定，主要是简单并列关系。
  • 低频条件可以通过展开显示。

不适用场景

  • AND / OR 条件组、嵌套查询或完整 QueryBuilder。
  • 保存筛选方案、共享筛选方案。
  • 表格请求、分页、导出和跨页面筛选管理。
  • UserPicker 等当前基础能力尚未闭环的复杂业务字段。

行为模型

FilterBar 区分两类值：

  • draftValues：当前填写值，字段变化立即更新。
  • activeValues：已生效查询值，只在 submit、change debounce 或 reset 提交成功后更新。

收起字段仍保留值、参与查询，并计入隐藏生效条件数量。visible: false 字段不渲染、不校验、不提交，也不计入隐藏生效条件。

字段类型

类型描述主要配置
input文本输入placeholder, allowClear, maxLength
select单选options, placeholder, allowClear, loading
multiSelect多选options, placeholder, allowClear, loading, maxTagCount
date日期placeholder, format, valueFormat, allowClear
dateRange日期区间placeholder, format, valueFormat, allowClear, span
cascader级联选择options, placeholder, allowClear, loading
treeSelect树选择treeData, placeholder, allowClear, loading

TreeSelect 的逻辑和 adapter 已存在，但当前视觉 V1 不计入完成口径；原因是 Vue TreeSelect 基础样式和双端 Popup 视觉尚未闭环。

Vue 提供 field scoped slot 作为有限 control 渲染扩展；label、help、error、布局和可访问性仍由 FilterBar 统一管理。 class 和 style 通过 Vue attrs fallthrough 传递到 FilterBar Root，不属于显式声明的 FilterBarProps。

AI Contract

使用 FilterBar 时，AI 必须：

  • 只为稳定、并列、低复杂度的筛选条件生成 FilterBar。
  • 为每个字段提供唯一 name。
  • 使用 defaultValue 表达 reset baseline，不把 reset 当成无条件清空。
  • 将请求、分页、导出、保存筛选等逻辑放在外部页面或表格能力中。
  • 不生成 treeSelect 作为视觉 V1 完成示例。

Evaluator

通过标准：

  • React / Vue 使用相同字段 Schema 和等价默认值。
  • manual 与 change 查询时机正确。
  • 收起字段保留值，并参与 active snapshot。
  • visible: false 不渲染、不校验、不提交。
  • Popup 不依赖无作用域 .arco-* 私有覆盖。
  • Docs Demo 调用真实组件，而不是静态 HTML 仿真。

警告标准：

  • 示例只覆盖单端。
  • 示例把页面容器样式混入 FilterBar 组件 API。
  • 响应式只依赖正文窄宽度，没有展示 4 / 3 / 2 / 1 列。

阻断标准：

  • React / Vue 行为不同。
  • 查询、重置或展开收起丢失值。
  • A/B 容器使用不同字段或不同数据。
  • Demo 中存在无作用域 .arco-* 覆盖或 !important。

当前限制

  • V1 不实现 UserPicker。
  • TreeSelect 逻辑存在，但视觉 V1 不计入完成；Popup 视觉一致性仍依赖基础组件闭环。
  • 不支持动态字段编排、重命名或 QueryBuilder。
  • 不负责表格请求、分页、导出、保存筛选、AND / OR 条件组。
