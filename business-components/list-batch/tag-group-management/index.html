标签与分组管理 TagGroupManagement

组件定义

TagGroupManagement 用于管理单层平铺的标签组，并提供当前分组状态、搜索和分组管理操作。右侧内容由调用方通过 React renderContent 或 Vue content slot 提供，组件不内置表格、分页、导出、请求或标签关系维护。

组件本体负责左侧管理区和左右主从布局；页面外层背景、卡片、固定高度等容器样式由页面或 Docs Preview 承接。

基本用法

基础示例使用真实的 React / Vue TagGroupManagement，展示左侧分组管理和右侧业务内容的主从结构。右侧的标签列表、工具栏和表格只是调用方提供的业务内容示例，不属于组件内置能力。新增、重命名和删除事件由 Demo 的父级更新 groups；组件本身不发请求、不持久化数据。

import { TagGroupManagement } from '@sbux/starbucks-design-react'
import type { TagGroupItem } from '@sbux/starbucks-design-react'
import { demoGroups, getDemoTags, type TagRecord } from './shared'

let nextGroupId = 0

function GroupContent({ groupId, groupName, records }: { groupId: string; groupName: string; records: TagRecord[] }) {
  return (
    <div className="sb-tag-group-management-demo__content">
      <div className="sb-tag-group-management-demo__content-header">
        <div>

      </div>
      <div className="sb-tag-group-management-demo__toolbar">
        <span>标签列表</span>
        <button type="button" className="sb-tag-group-management-demo__content-button">
          新增标签
        </button>
      </div>

            </tr>
          </thead>
          <tbody>
            {records.map((record) => (
              <tr key={`${groupId}-${record.name}`}>
                <td>{record.name}</td>
                <td>
                  <span data-status={record.status === '启用' ? 'active' : 'inactive'}>{record.status}</span>
                </td>
                <td>{record.updatedAt}</td>
                <td>
                  <button type="button" className="sb-tag-group-management-demo__text-button">
                    编辑
                  </button>
                </td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </div>
  )
}

          cancelText: '取消'
        })}
        onCreateGroup={(name) => setGroups((current) => [...current, { id: `group-${++nextGroupId}`, name }])}
        onRenameGroup={(groupId, name) =>
          setGroups((current) => current.map((group) => (group.id === groupId ? { ...group, name } : group)))

          )
        }
      />
    </div>
  )
}

受控模式

通过外部 activeGroupId 和按钮切换当前分组，React 使用 onActiveGroupChange，Vue 使用 activeGroupChange / update:activeGroupId。右侧内容随外部选中状态同步变化。

Show code
代码示例 
import { useState } from 'react'
import { TagGroupManagement } from '@sbux/starbucks-design-react'
import type { TagGroupItem } from '@sbux/starbucks-design-react'
import { demoGroups, getDemoTags } from './shared'

function ControlledContent({ group }: { group: TagGroupItem | null }) {
  const records = group ? getDemoTags(group.id) : []
  return group ? (
    <div className="sb-tag-group-management-demo__content">
      <div className="sb-tag-group-management-demo__content-header">
        <div>
          <span className="sb-tag-group-management-demo__eyebrow">外部 activeGroupId</span>
          <h3>{group.name}</h3>
        </div>
        <span className="sb-tag-group-management-demo__count">{records.length} 个标签</span>
      </div>
      <div className="sb-tag-group-management-demo__table-wrap">
        <table>
          <thead>
            <tr>
              <th>标签名称</th>
              <th>状态</th>
              <th>更新时间</th>
            </tr>
          </thead>
          <tbody>
            {records.map((record) => (
              <tr key={`${group.id}-${record.name}`}>
                <td>{record.name}</td>
                <td>{record.status}</td>
                <td>{record.updatedAt}</td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </div>
  ) : (
    <p className="sb-tag-group-management-demo__placeholder">当前没有选中的标签组。</p>
  )
}

export default function TagGroupManagementControlledDemo() {
  const [activeGroupId, setActiveGroupId] = useState<string | null>('store')
  const activeGroup = demoGroups.find((group) => group.id === activeGroupId) ?? null

  return (
    <div className="sb-tag-group-management-demo sb-tag-group-management-demo--controlled">
      <div className="sb-tag-group-management-demo__external-controls" aria-label="外部切换标签组">
        <span>外部控制：</span>
        {demoGroups
          .filter((group) => !group.disabled)
          .slice(0, 4)
          .map((group) => (
            <button
              key={group.id}
              type="button"
              aria-pressed={group.id === activeGroupId}
              onClick={() => setActiveGroupId(group.id)}
            >
              {group.name}
            </button>
          ))}
      </div>
      <p className="sb-tag-group-management-demo__event-status" aria-live="polite">
        当前 activeGroupId：{activeGroupId ?? 'null'}
      </p>
      <TagGroupManagement
        groups={demoGroups}
        activeGroupId={activeGroupId}
        onActiveGroupChange={(groupId) => setActiveGroupId(groupId)}
        renderContent={() => <ControlledContent group={activeGroup} />}
      />
    </div>
  )

暂不支持

V1 暂不支持维度分类模式、批量管理模式、多级树、拖拽排序、Checkbox、标签跨分组移动、分页、导出和组件内请求。需要这些能力时，应由页面组合现有基础组件或另行设计业务组件。

Anatomy

分组选择按钮与重命名、删除按钮是同级的独立操作。列表使用 ul，选择按钮使用 aria-current 表示当前分组；操作按钮有独立的可访问名称。

适用场景

  • 左侧单层标签组管理，右侧承载列表、表格或业务详情。
  • 需要统一分组切换、搜索、新增、重命名和删除确认交互的管理页面。
  • 由页面负责请求和数据关系，组件负责稳定的管理区交互。

不适用场景

  • 多级树、拖拽排序或跨分组移动。
  • 组件自身需要维护标签关系、表格请求、分页或导出。
  • 需要 readonly 但仍保留部分管理入口的场景，V1 暂不提供 readonly。

行为规则

  • activeGroupId 提供时为受控模式；未提供时使用 defaultActiveGroupId 初始化非受控状态。
  • activeGroupId={null} 明确表示受控无选中项，公开事件也统一使用 string | null。
  • 非受控初始化在首次 loading=false 时只解析一次，优先使用有效且未禁用的 defaultActiveGroupId，否则选择第一个可用分组。
  • 搜索只匹配分组名称，输入和名称会先去除首尾空格；搜索回调在 500ms debounce 后触发，搜索不会改变当前分组。
  • 组件不修改外部 groups。新增、重命名和删除事件表示经过组件校验后的操作意图，接口结果和数据更新由调用方处理。
  • 当前分组被外部数据删除时，非受控模式按原位置优先选择下一项、再选择上一项；受控模式等待调用方更新。
  • loading 和 disabled 只影响左侧管理区；右侧 renderContent / content slot 保持渲染。

AI Contract

Trigger

当页面需要管理单层标签组，并在右侧承载与当前分组相关的自定义业务内容时，选择 TagGroupManagement。

Do not use

不要用于多级树、拖拽排序、标签关系维护、跨分组移动、表格分页导出或需要组件直接请求接口的场景。

Selection priority

优先确认页面是否只需要左侧分组管理；右侧内容应由调用方传入。只有在需要新增、重命名、删除和搜索等稳定管理交互时才使用该组件。

Generation Rules

  1. groups 必须从调用方传入，id 必须唯一。
  2. 需要受控选择时传入 activeGroupId，明确无选中项时传入 null；否则使用 defaultActiveGroupId。
  3. React 使用 renderContent，Vue 使用 content slot；不要在组件外复制左侧状态机。
  4. 操作事件只表示用户意图，事件处理器负责更新 groups 和调用接口。
  5. 页面高度由外层容器提供，不能为组件增加固定业务高度配置。

Known Pitfalls

  • 受控模式下组件不会替调用方更新 activeGroupId 或 groups。
  • loading 和 disabled 不会自动禁用右侧内容。
  • allowDelete=false 隐藏全局删除能力，单项 allowDelete=false 会保留禁用入口并可用 Tooltip 说明原因。
  • Tree、批量管理和 readonly 不属于当前 V1。
